PGBloom Overview

PGBloom is a PostgreSQL-first infrastructure toolkit for JavaScript and TypeScript. The project stores its durable state in PostgreSQL and exposes high-level primitives for coordination, persistence, messaging, and model access.

What it is

  • PostgreSQL-backed cache with optional Bloom-filter acceleration.
  • LISTEN/NOTIFY Pub/Sub and persistent event history.
  • Priority job queue with visibility timeouts and retries.
  • Distributed locks and leader election with TTL renewal.
  • Scheduler for delayed and recurring jobs.
  • Rate limiting using fixed-window, sliding-window, and token-bucket algorithms.
  • Atomic counters and event-driven integrations.
  • Schema-driven CRUD model layer.
  • Authentication, sessions, JWTs, and OTP flows.
  • Local SSDiskDB and in-memory LRU/TTL cache wrappers.

Why it exists

PostgreSQL is already the durable system of record in many applications. PGBloom keeps coordination logic in the same database and avoids introducing Redis or a separate queue broker unless the app genuinely needs one.

When to use it

  • Need a queue, lock, or scheduler backed by SQL transactions.
  • Want Redis-like features without extra infrastructure.
  • Need per-application state with PostgreSQL tables and notifications.

When not to use it

  • Need a full React integration library; this project does not ship React hooks or providers.
  • Need a browser-only database client; use the server runtime and HTTP/RPC for database-backed features.
  • Need a general-purpose distributed event bus with heavy stream semantics beyond this project’s table-based design.

Architecture

Application → PGBloom client → PostgreSQL. Optional local path: MemoryCache → SSDiskStore → local disk. Browser code uses the browser entry and calls backend services over HTTP/RPC.

Public API

The primary public entry is createPgbloom(), exported from src/index.ts and src/server.ts. The library also exports runtime-safe browser utilities from the pgbloom/browser entrypoint.
